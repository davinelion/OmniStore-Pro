Features

A full store, not a directory

Everything is served from the OmniSource v1 contract and validated with shared zod schemas before it reaches the screen — malformed data degrades a section, it never crashes a page.

Full-text search

Typo tolerance, synonyms, ranked fields and facets — with shareable URLs for every result set.

Deep filtering

Platform (any-of / all-of), category, licence, architecture, package type, open-source only, minimum trust or quality, freshness.

Real downloads

Platform-aware links to validated release assets only — size, architecture and checksum shown, then a clean install hand-off.

Release history

Every app ships its full version history — sanitised notes, pre-release labels, versions and dates.

Computed alternatives

Derived from shared categories and platforms — never hand-written, never stale.

Side-by-side comparison

Pick up to four apps, read them in a table, and share the exact comparison by URL.

Track any source

Paste a GitHub, GitLab, F-Droid, Flathub, Winget or Homebrew URL — OmniStore watches releases and diffs versions into your update inbox.

Personal library

Favorites, follows, private notes and portable backups — all device-local, no account, nothing uploaded.

Installable PWA

Works from the home screen with an offline shell and cached API responses — the store keeps working on the subway.

Light · Dark · System

Theme switching without flash, and the whole site respects prefers-reduced-motion.

A Next.js web client — indexed, installable and accessible. It reads through a same-origin /api/v1 proxy, validates every response with shared zod schemas, and degrades section-by-section instead of ever showing an error page.

API contract

One contract for every client

Browsers, native clients and scripts all read the same /api/v1 surface. Both the live OmniSource and the bundled feed implement it identically — nothing above the transport knows which one answered.

Honesty rules

Product requirements, not preferences

A store that invents data is worse than no store. These five rules are enforced by design, in the OmniStore Pro codebase.

01

Nothing is invented

Missing upstream data renders as “Not available” — no fake descriptions, ratings, reviews, screenshots, versions or sizes.

02

Only VALID packages are downloads

INVALID, QUARANTINED and REVIEW_REQUIRED assets are shown with their real status; unknown ones say “Verification unavailable”.

03

Verification is not a malware guarantee

OmniStore never claims to be one. Scores are computed from public signals and always displayed with their contributing factors.

04

Only https leaves the app

Release notes are sanitised before rendering — no upstream HTML, javascript: links, iframes or inline handlers.

05

Binaries are never mirrored

Downloads go straight to the upstream release host. OmniStore points the way; it never holds your binary.

Get started

Up and running in one minute

Requires Node 22.12+. A fresh clone renders a complete store with zero configuration — the validated feed snapshot is bundled. For production, set OMNISOURCE_API_URL to a live OmniSource deployment.

bash 
# from the repo root
npm install
cp .env.example .env.local   # optional — every variable has a safe default
npm run dev                  # → http://localhost:3000
bash · Vercel / Netlify / any Node host 
# build & run (Node ≥ 22.12)
npm ci && npm run build && npm start

# post-deploy checks
curl -fsS "https://your-host/api/v1/health"      # status should be "ok"
curl -fsS "https://your-host/sitemap.xml" | head  # lists /apps/… URLs
bash · Docker 
docker build -t omnistore .
docker run -p 3000:3000 omnistore
Static hosting is not supported: search, feeds, sitemap and caching are server-rendered by design. Refresh the bundled feed from upstream with npm run ingest (needs a GitHub token).

FAQ

Questions, answered honestly

What is OmniStore Pro?
A universal discovery and distribution interface for open-source applications — one store for iOS, iPadOS, Android, Windows, macOS and Linux. It is a client of OmniSource Pro: OmniSource supplies metadata, validation, search and feeds, and OmniStore presents them.
Where does the catalog data come from?
Two interchangeable paths: a live OmniSource deployment when OMNISOURCE_API_URL is set, or the validated feed snapshot committed in data/omnisource-feed.json (currently 444 apps, 1,891 releases, 13,357 assets). The UI contains no mock catalog or hand-authored app data — the snapshot is produced by npm run ingest from real upstream repositories, and every page shows when the data was generated.
Do I need an account? Is it free?
No account, ever. OmniStore Pro is free and open source. Favorites, follows, tracked sources, notes and comparison selections live in your browser and IndexedDB on your device — nothing is uploaded or synced. Account sync is designed for but not yet implemented.
Does “validated” mean the software is malware-free?
No — and OmniStore never claims it is. Validation covers metadata integrity, release-asset checks, licence provenance and repository activity. Verification is not a malware guarantee: only assets with status VALID are offered as downloads, scores are shown with their contributing factors, and downloads always go to the upstream release host, never through OmniStore.
Can I track releases of apps that aren't in the catalog yet?
Yes. Paste any GitHub, GitLab, Codeberg, Forgejo, F-Droid, Flathub, Winget or Homebrew URL on the /track page. If OmniSource knows the app you get its latest version and platforms; if not, it is tracked as awaiting indexing and you can request it from OmniSource. “Check for updates” diffs real versions, so the update inbox never reports a change that didn't happen.
How is it built, and can I contribute?
Next.js 15 App Router, React, TypeScript, Tailwind — with a framework-neutral OmniSource SDK, shared zod contracts in packages/shared-models, and test suites for unit, component, contract, integration, performance and Playwright e2e. Run npm run verify before sending a pull request. The developer guide covers extension and locale rules.
